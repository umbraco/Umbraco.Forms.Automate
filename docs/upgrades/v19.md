## Follow-ups

- **First boot of a fresh SQLite demo fails** on CMS 19 rc1: `DistributedWriteLockTimeoutException`
  (write lock -345) during the Clean package migration (`UnattendedUpgrader.RunPackageMigrationsAsync`
  → `DocumentUrlService.RebuildAllUrlsAsync` → `SqliteDistributedLockingMechanism`). Same with
  `Cache=Shared` forced back on, so not caused by this upgrade's change. A second start boots.
  Not checked on v18. Possibly a CMS rc1 issue: report upstream once reproduced without Clean.
- **Export Form Entries can miss an entry submitted moments earlier** (smoke, 12-11-2026: 0
  entries on the triggered run, the entry on a replay ~55 s later). Cause: `ExportEntriesAction`
  reads `IRecordReaderService`, which is backed by the Forms search index
  (Forms `src/Umbraco.Forms.Examine/Services/RecordReaderService.cs:179-188`). The trigger fires
  after commit (CMS `Scope.cs:543-580,644-648`), but the index catches up asynchronously. Not
  caused by the upgrade: v18 reads the same index (re-indexed on the background queue after the
  scope), so it very likely races too (not reproduced on v18). Applies to website submissions
  as well, not only nested runs. Possible fix in this package: read from the database with
  `IFormRecordSearcher.QueryDataBase(formId, RecordFilter)` (check its sensitive-field handling);
  or document that Export reflects the search index. Decision pending (Rick).
- For the Forms team: Forms 19 indexes a record from `RecordSavingNotification`, inside the
  transaction and before the insert (`RecordStorage.cs:256-264`), so a rolled-back submit can
  leave an orphan index document; v18 waited for the scope to complete.

- The demo's Razor views already fail on v18: `Views/Partials/blocklist/default.cshtml:8`
  (`ContentUdi`), `mainNavigation.cshtml:21` and `xmlSitemap.cshtml:14,16,29` (`Children`).
  `/contact/` fails on a fresh database because no form is seeded.
- Open PR #18 (`feature/delete-entry-action`) will need a v19 port.
- Building on v19 adds untracked `appsettings-schema.Umbraco.Automate.json` and
  `appsettings-schema.Umbraco.Cms.Search.Examine.json`; the CMS 19 template gitignores
  `appsettings-schema*.json`. Decide whether to track or ignore them.
- Optional template alignment: the `UmbracoUseAppLocalIcu` property and Kestrel-first launch
  profiles.
- Test-only dependency bumps to match the CMS (Microsoft.NET.Test.Sdk 18.x, Moq 4.21.0).
- `appsettings.Development.json:32` commits the demo's unattended admin password (local only).
